---
title: Quick Start
description: Convert a fresh Laravel project to layers and create your first one.
---

This guide starts from a fresh Laravel project. On an existing project, skip `osdd:start` and go straight to [your first layer](#create-your-first-layer).

## Create the project

```bash
composer create-project laravel/laravel my-app
cd my-app
composer require lomkit/laravel-osdd
```

## Convert it to layers

```bash
php artisan osdd:start
```

The command first asks for confirmation:

```
┌ osdd:start deletes app/, config/ and database/ (database/database.sqlite is kept). Continue? ┐
│ ○ Yes / ● No                                                                                 │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

Then it:

1. Creates the `functional/users` layer: the `User` model, its factory, seeder and migration, and a `UsersServiceProvider` that points Laravel's auth provider to the layer's `User` model.
2. Creates the `technical/osdd` layer, which holds the OSDD configuration and the cache and jobs migrations of the skeleton, and makes the layer seeders the default seeder of `db:seed`.
3. Registers both layers in the root `composer.json`.
4. Removes the `App\Providers\...` entries from `bootstrap/providers.php`: layer providers are discovered through Composer.
5. Deletes `app/` and `config/`, empties `database/` except `database/database.sqlite`, and removes the `Database\Factories\` and `Database\Seeders\` autoload entries.
6. Asks to run `composer update functional/users technical/osdd` to install both layers.

Your project now looks like this:

```
functional/
  users/
    composer.json
    src/
      Models/User.php
      Providers/UsersServiceProvider.php
    database/
      factories/UserFactory.php
      migrations/0001_01_01_000000_create_users_table.php
      seeders/UsersSeeder.php
technical/
  osdd/
    composer.json
    config/osdd.php
    database/
      migrations/0001_01_01_000001_create_cache_table.php
      migrations/0001_01_01_000002_create_jobs_table.php
    src/
      Providers/OsddServiceProvider.php
database/
  database.sqlite
composer.json     ← path repositories for functional/* and technical/*
```

The default SQLite connection keeps working. Create the tables:

```bash
php artisan migrate
```

:::tip
In a script or a CI job, pass `--force` to skip the confirmation and `--composer-update` to install the layers: `php artisan osdd:start --force --composer-update`.
:::

## Create your first layer

```bash
php artisan osdd:layer
```

The command asks:

1. Where to create the layer: `functional` or `technical`.
2. The layer name, such as `orders`.
3. Which files to generate. The default selection creates a migration, a model, a factory, a service provider and a test.

Then it registers `functional/orders` in the root `composer.json` and offers to run `composer update functional/orders`.

```
functional/orders/
├── composer.json
├── src/
│   ├── Models/Order.php
│   └── Providers/OrdersServiceProvider.php
├── database/
│   ├── factories/OrderFactory.php
│   └── migrations/xxxx_xx_xx_xxxxxx_create_orders_table.php
└── tests/
    └── Feature/OrdersTest.php
```

Without a terminal, name the layer and pick the generators:

```bash
php artisan osdd:layer functional/orders --generators=migration,model,factory,provider,test --composer-update
```

## Generate code inside the layer

Every generator takes a `--layer` option with the layer's name:

```bash
php artisan osdd:controller OrderController --layer=functional/orders
```

The controller lands in `functional/orders/src/Http/Controllers`, not in `app/`. `--layer=orders` works too while no other layer is named `orders`. Without `--layer`, the command asks you to pick a layer; without a terminal, `--layer` is required.

## Run the layers

```bash
php artisan migrate        # every layer's migrations
php artisan osdd:seed      # every layer's seeders
php artisan osdd:phpunit   # one test suite per layer in phpunit.xml
php artisan test
```

## Keep the boundaries

When a layer starts using another one, declare it. For a new layer, pass `--requires`:

```bash
php artisan osdd:layer functional/invoices --requires=functional/orders
```

Then check that every layer only uses the layers it requires:

```bash
php artisan osdd:check
```

```
  ERROR  functional/orders uses functional/billing but does not require it.

  functional/orders/src/Checkout.php:7 ............ Functional\Billing\Models\Invoice
```

:::tip
Read [Layers](/layers/basics) to understand what makes a folder a layer, then [Boundaries](/layers/boundaries) to run `osdd:check` in CI.
:::
