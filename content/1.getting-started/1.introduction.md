Laravel OSDD (Open Source Driven Development) splits a Laravel application into **layers**. A layer is a Composer package that lives in your repository, with its own models, migrations, seeders, tests, routes and service provider.

The default `app/`, `database/` and `config/` folders give way to two folders at the root of the project:

- `functional/` holds the business domains: `users`, `orders`, `billing`.
- `technical/` holds the shared infrastructure: the OSDD configuration, authentication wiring, observability.

## Why layers

A fresh Laravel application keeps every domain in the same folders:

```
app/
  Models/User.php
  Models/Order.php
  Models/Invoice.php
  Http/Controllers/UserController.php
  Http/Controllers/OrderController.php
  ...
```

Nothing separates billing from orders. Migrations, seeders and tests are global, and a change in one domain means browsing folders shared with every other one.

With OSDD, each domain owns its package:

```
functional/
  users/
    composer.json        ← package "functional/users"
    src/
      Models/User.php
      Providers/UsersServiceProvider.php
    database/
      migrations/
      factories/
      seeders/
    tests/
  orders/
    composer.json        ← package "functional/orders", requires "functional/users"
    src/
      Models/Order.php
      Providers/OrdersServiceProvider.php
    database/
    tests/
technical/
  osdd/
    composer.json        ← package "technical/osdd"
    config/osdd.php
    src/
      Providers/OsddServiceProvider.php
```

A layer declares the layers it depends on in the `require` section of its `composer.json`, so the dependencies between domains stay visible. Each layer has its own test suite, its own seeders and its own configuration.

## Boundaries you can check

All layers share one Composer autoloader, so PHP lets `functional/orders` use a class of `functional/billing` even when `functional/orders` does not require it. [`osdd:check`](/commands/osdd-check) closes that gap: it reads the PHP files of every layer and fails when a layer uses a layer it does not require, or when layers require each other. Run it in CI to keep the boundaries written in each `composer.json` true. See [Boundaries](/layers/boundaries).

## What the package gives you

- [`osdd:start`](/commands/osdd-start) converts a fresh Laravel project to layers.
- [`osdd:layer`](/commands/osdd-layer) creates a layer and registers it in your root `composer.json`; [`osdd:remove`](/commands/osdd-remove) removes one.
- The [`osdd:*` generators](/commands/make-commands) are twins of every `make:*` generator of Laravel and write inside the layer you pick.
- [`osdd:list`](/commands/osdd-list), [`osdd:check`](/commands/osdd-check) and [`osdd:graph`](/commands/osdd-graph) show the layers, check their boundaries and draw their graph.
- [`osdd:seed`](/commands/osdd-seed) runs the seeders every layer registers, and [`osdd:phpunit`](/commands/osdd-phpunit) adds one test suite per layer to `phpunit.xml`.
- [`LayerServiceProvider`](/layers/service-provider) loads a layer's migrations, seeders, routes, configuration, [views, translations and components](/layers/views-and-components).
- [Layer listeners](/layers/events) can be discovered like the ones of `app/Listeners`, and [`php artisan optimize`](/commands/osdd-cache) caches the layers in production.
- Optional [Livewire](/integrations/livewire) and [Filament](/integrations/filament) support, and a [Laravel Boost](/integrations/laravel-boost) skill that teaches your coding agent where files go.

## Requirements

- PHP **8.3** or higher
- Laravel **13.0** or higher
- The `dom` PHP extension
