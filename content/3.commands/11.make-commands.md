title: Generators
description: The osdd:* twins of Laravel's make:* commands write inside a layer.
---

Each `osdd:*` generator extends its `make:*` twin and takes the same arguments and options. The difference: the file lands inside a layer, under the layer's namespace.

```bash
php artisan osdd:model Order --layer=functional/orders
# functional/orders/src/Models/Order.php
```

## The --layer option

`--layer` takes the layer's package name, as written in its `composer.json`:

```bash
php artisan osdd:controller OrderController --layer=functional/orders
```

Without `--layer`, the command asks you to search and pick a layer. An unknown name stops the command with `Layer 'functional/order' not found.`

:::note
`--layer` only matches the full package name. A short name such as `--layer=orders` or a path such as `--layer=functional/orders/src` is not found.
:::

## Generators that wire the provider

Four generators also update the layer, so the new file is loaded without editing anything:

| Command | Adds |
|---------|------|
| `osdd:migration` | `$this->loadMigrationsFrom(__DIR__ . '/../../database/migrations');` to the layer provider |
| `osdd:seeder` | `$this->loadSeeders([\Functional\Orders\Database\Seeders\OrdersSeeder::class]);` to the layer provider |
| `osdd:config` | `$this->overrideConfigFrom(__DIR__ . '/../../config/orders.php', 'orders');` to the layer provider |
| `osdd:provider` | The new provider to `extra.laravel.providers` in the layer's `composer.json` |

The first three edit `src/Providers/<Package>ServiceProvider.php`, such as `OrdersServiceProvider.php`, and add the line at the end of the method that comes before `register()`, `boot()` in a generated provider. They do nothing when the provider is missing or already contains the line.

:::warning
Move the `overrideConfigFrom()` line added by `osdd:config` to `register()`. See [Configuration](/layers/configuration).
:::

## Examples

### Model and its companions

`osdd:model` accepts the options of `make:model` and creates every companion in the same layer:

```bash
php artisan osdd:model Order --layer=functional/orders --factory --migration --seed --policy --resource --requests
```

```
functional/orders/
├── src/Models/Order.php
├── src/Policies/OrderPolicy.php
├── src/Http/Controllers/OrderController.php
├── src/Http/Requests/StoreOrderRequest.php
├── src/Http/Requests/UpdateOrderRequest.php
└── database/
    ├── factories/OrderFactory.php
    ├── migrations/<timestamp>_create_orders_table.php
    └── seeders/OrderSeeder.php
```

`--all` turns on the factory, migration, seeder, policy and resource controller at once. Unlike `make:model`, `osdd:model` does not ask which companions to create: pass the options.

### Migration

```bash
php artisan osdd:migration add_status_to_orders_table --table=orders --layer=functional/orders
# functional/orders/database/migrations/<timestamp>_add_status_to_orders_table.php
```

### Event and listener

```bash
php artisan osdd:event OrderPlaced --layer=functional/orders
php artisan osdd:listener SendOrderConfirmation --event=OrderPlaced --layer=functional/orders
```

### Command

```bash
php artisan osdd:command PruneAbandonedOrders --layer=functional/orders
# functional/orders/src/Console/Commands/PruneAbandonedOrders.php
```

Register it in the layer provider with `$this->commands([...])`, or call it from the layer's `routes/console.php`.

### Provider

```bash
php artisan osdd:provider OrderEventsServiceProvider --layer=functional/orders
# functional/orders/src/Providers/OrderEventsServiceProvider.php, listed in the layer's composer.json
```

Run `composer update functional/orders` so Laravel discovers it.

### Test

```bash
php artisan osdd:test PlaceOrderTest --layer=functional/orders
# functional/orders/tests/Feature/PlaceOrderTest.php
```

## Referencing another layer

Options such as `--model` resolve short names inside the current layer: `--model=Order` means `Functional\Orders\Models\Order`. For a model of another layer, generate the class without `--model` and add the import by hand.
