---
title: osdd:seed
description: Run the seeders registered by every layer.
---

`osdd:seed` runs every seeder a layer registered with `loadSeeders()`, in priority order.

```bash
php artisan osdd:seed
```

## Options

| Option | Description |
|--------|-------------|
| `--fresh` | Run `migrate:fresh` before seeding: drop every table and run every migration. |
| `--refresh` | Run `migrate:refresh` before seeding: roll back and run every migration. |

```bash
php artisan osdd:seed --fresh
```

With both options, `--fresh` wins. If the migration step fails, nothing is seeded.

## Registering seeders

A layer registers its seeders in its service provider:

```php [functional/orders/src/Providers/OrdersServiceProvider.php]
use Functional\Orders\Database\Seeders\OrdersSeeder;
use Functional\Orders\Database\Seeders\OrderStatusesSeeder;

public function boot(): void
{
    if ($this->app->runningInConsole()) {
        $this->loadSeeders([
            OrderStatusesSeeder::class,
            OrdersSeeder::class,
        ]);
    }
}
```

`osdd:seeder OrdersSeeder --layer=functional/orders` creates the seeder and adds the `loadSeeders()` call for you. A seeder you write by hand needs the call too.

## Order

Seeders run by ascending priority, `0` by default. Seeders with the same priority run in registration order.

```php
// Reference data first
$this->loadSeeders([RolesSeeder::class], priority: -10);

// Default priority
$this->loadSeeders([OrdersSeeder::class]);

// Needs the orders
$this->loadSeeders([InvoicesSeeder::class], priority: 10);
```

Use priorities across layers: the `users` layer seeds roles at `-10`, the `billing` layer seeds invoices at `10`, whatever the order Laravel boots their providers in.

## How it works

`loadSeeders()` pushes the classes into the `Lomkit\Osdd\SeederRegistry` singleton. `osdd:seed` reads the registry and calls `db:seed --class=<seeder>` for each class. A class that does not exist is skipped with a warning.

```php [functional/orders/database/seeders/OrdersSeeder.php]
<?php

namespace Functional\Orders\Database\Seeders;

use Functional\Orders\Models\Order;
use Illuminate\Database\Seeder;

class OrdersSeeder extends Seeder
{
    public function run(): void
    {
        Order::factory()->count(50)->create();
    }
}
```

:::note
There is no central `DatabaseSeeder` in an OSDD project: each layer registers its own seeders, and adding a layer never touches a shared file.
:::
