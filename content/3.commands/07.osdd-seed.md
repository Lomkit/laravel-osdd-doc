---
title: osdd:seed
description: Run the seeders registered by every layer, or by some layers.
---

`osdd:seed` runs every seeder a layer registered with `loadSeeders()`, in priority order.

```bash
php artisan osdd:seed
```

## Options

| Option | Description |
|--------|-------------|
| `--layer` | Only run the seeders of these layers. Full or package name, repeated or comma-separated. |
| `--fresh` | Run `migrate:fresh` before seeding: drop every table and run every migration. |
| `--refresh` | Run `migrate:refresh` before seeding: roll back and run every migration. |
| `--database` | The database connection to migrate and seed. |
| `--force` | Run in production without asking. |

```bash
php artisan osdd:seed --fresh
php artisan osdd:seed --fresh --force --database=reporting
php artisan osdd:seed --layer=functional/orders --layer=billing
```

`--fresh` and `--refresh` cannot be combined. `--database` and `--force` are forwarded to `db:seed`, and to `migrate:fresh` or `migrate:refresh`.

## Exit codes

`osdd:seed` returns the exit code of the step that failed:

- when `migrate:fresh` or `migrate:refresh` fails, nothing is seeded and the command returns its code;
- otherwise it returns the exit code of `db:seed`.

A seeder that throws stops the run: the next seeders do not run. A class registered with `loadSeeders()` that does not exist fails the run before any seeder runs, with `Lomkit\Osdd\Seeders\SeederNotFoundException`, so a typo in a provider fails `osdd:seed` and your CI.

In production, `db:seed` asks for confirmation once. A cancelled run seeds nothing and exits with 1. Without a terminal, `db:seed` cancels itself: pass `--force`.

## Seeding some layers

```bash
php artisan osdd:seed --layer=functional/orders --layer=billing
php artisan osdd:seed --layer=orders,billing
```

Only the seeders whose class belongs to those layers run, still in priority order. A seeder belongs to the layer with the longest matching `psr-4` prefix. Names resolve like the generators' `--layer`: an unknown or ambiguous name fails with exit code 1 before anything runs, `--fresh` included. A selected layer without seeders prints `No OSDD seeders registered for functional/orders.`.

## Registering seeders

A layer registers its seeders in its service provider:

```php [functional/orders/src/Providers/OrdersServiceProvider.php]
use Functional\Orders\Database\Seeders\OrdersSeeder;
use Functional\Orders\Database\Seeders\OrderStatusesSeeder;

public function boot(): void
{
    $this->loadSeeders([
        OrderStatusesSeeder::class,
        OrdersSeeder::class,
    ]);
}
```

`osdd:seeder OrdersSeeder --layer=functional/orders` creates the seeder and adds the `loadSeeders()` call for you. A seeder you write by hand needs the call too.

## Order

Seeders run by ascending priority, `0` by default. Seeders with the same priority run in registration order. A seeder registered twice runs once, at its first priority.

```php
// Reference data first
$this->loadSeeders([RolesSeeder::class], priority: -10);

// Default priority
$this->loadSeeders([OrdersSeeder::class]);

// Needs the orders
$this->loadSeeders([InvoicesSeeder::class], priority: 10);
```

Use priorities across layers: the `users` layer seeds roles at `-10`, the `billing` layer seeds invoices at `10`, whatever the order Laravel boots their providers in.

## How it works

`loadSeeders()` pushes the classes into the [`SeederRegistry`](/api-reference/seeder-registry). `osdd:seed` runs `db:seed --class="Lomkit\Osdd\Seeders\LayersSeeder"` once, after `--fresh` or `--refresh`. [`LayersSeeder`](/api-reference/seeder-registry#layersseeder) reads the registry and calls each seeder.

```php [functional/orders/database/seeders/OrdersSeeder.php]
<?php

namespace Functional\Orders\Database\Seeders;

use Functional\Orders\Models\Order;
use Illuminate\Database\Seeder;

class OrdersSeeder extends Seeder
{
    public function run(): void
    {
        Order::factory()->count(50)->create();
    }
}
```

## With Laravel's commands and tests

`LayersSeeder` also works with Laravel's own seeding:

```bash
php artisan db:seed --class="Lomkit\Osdd\Seeders\LayersSeeder"
php artisan migrate:fresh --seed --seeder="Lomkit\Osdd\Seeders\LayersSeeder"
```

```php [functional/orders/tests/Feature/PlaceOrderTest.php]
use Illuminate\Foundation\Testing\RefreshDatabase;
use Lomkit\Osdd\Seeders\LayersSeeder;

class PlaceOrderTest extends TestCase
{
    use RefreshDatabase;

    protected bool $seed = true;

    protected string $seeder = LayersSeeder::class;
}
```

Pass the full class name: Laravel prefixes a name without a backslash with `Database\Seeders\`, so `--seeder=LayersSeeder` is not found.

After [`osdd:start`](/commands/osdd-start), `LayersSeeder` is the default seeder, so `php artisan db:seed`, `migrate --seed`, `migrate:fresh --seed` and `RefreshDatabase` with only `$seed = true` run the layer seeders without naming it.

:::note
There is no central `DatabaseSeeder` in an OSDD project: each layer registers its own seeders, and adding a layer never touches a shared file. A real `Database\Seeders\DatabaseSeeder` class, if you write one, takes precedence over the binding.
:::
