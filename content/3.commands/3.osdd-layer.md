---
title: osdd:layer
description: Create a layer, generate its first files and register it in Composer.
---

`osdd:layer` creates a layer, runs the generators you pick and registers the layer in the root `composer.json`.

## Interactive

```bash
php artisan osdd:layer
```

The command asks:

1. **Where to create the layer**, among the keys of `osdd.layers.paths` (`functional` or `technical`). With a single path, it skips the question. The key becomes the vendor of the package.
2. **The layer name**, such as `orders`: lowercase letters, numbers and hyphens.
3. **Which generators to run.** See [the list below](#generators).
4. **Whether to install the layer** with `composer update functional/orders`.

```
┌ Where should the layer be created? ──────────────────────────┐
│ › ● functional                                               │
│   ○ technical                                                │
└──────────────────────────────────────────────────────────────┘

┌ Layer name ──────────────────────────────────────────────────┐
│ orders                                                       │
└──────────────────────────────────────────────────────────────┘

┌ Which generators should be run? ─────────────────────────────┐
│ › ◼ migration                                                │
│   ◼ model                                                    │
│   ◼ factory                                                  │
│   ◻ seeder                                                   │
│   ◼ service-provider                                         │
│   ◼ test                                                     │
│   ◻ controller                                               │
│   ◻ policy                                                   │
│   ◻ routes                                                   │
└──────────────────────────────────────────────────────────────┘
```

## With arguments

```bash
php artisan osdd:layer functional/orders \
    --target-path="$(pwd)/functional" \
    --generators=migration \
    --generators=model \
    --generators=factory \
    --generators=service-provider
```

| Argument / Option | Description |
|-------------------|-------------|
| `name` | Composer package name of the layer, `vendor/package`. |
| `--target-path` | Absolute path of the folder to create the layer in. Without it, the command asks. |
| `--generators` | Generator to run. Repeat the option for each one. Without it, the command asks. |

The layer is created in `<target-path>/<package>`, and its namespace comes from the name: `functional/orders` gives `Functional\Orders`.

:::warning
Repeat `--generators` for each generator. A comma-separated list such as `--generators=model,factory` is read as a single unknown name, and the layer only gets its `composer.json`.
:::

## Generators

For a layer named `functional/orders`:

| Generator | Default | Creates |
|-----------|:-------:|---------|
| `migration` | ✓ | `database/migrations/<timestamp>_create_orders_table.php` |
| `model` | ✓ | `src/Models/Order.php` |
| `factory` | ✓ | `database/factories/OrderFactory.php` |
| `service-provider` | ✓ | `src/Providers/OrdersServiceProvider.php` |
| `test` | ✓ | `tests/Feature/OrdersTest.php` |
| `seeder` | | `database/seeders/OrdersSeeder.php` |
| `controller` | | `src/Http/Controllers/OrdersController.php` |
| `policy` | | `src/Policies/OrdersPolicy.php`, bound to the `Order` model when `model` runs too |
| `routes` | | `routes/web.php`, `routes/api.php`, `routes/console.php`, `routes/channels.php` |

The model takes the singular of the layer name and the table its plural: `external-accounts` gives the `ExternalAccount` model and the `external_accounts` table. With both `model` and `factory`, the model is generated with its factory.

The `service-provider` generator also lists the provider under `extra.laravel.providers` in the layer's `composer.json`. Its `boot()` method loads the layer's migrations and seeder, and calls [`withRouting()`](/layers/routing) with the four route files. Missing route files are skipped, so the call is safe without the `routes` generator.

:::note
The generated provider registers `OrdersSeeder` even when the `seeder` generator does not run. `osdd:seed` then warns that the class is missing: select `seeder`, or remove the `loadSeeders()` line from the provider.
:::

## What gets registered

Whatever the generators, `osdd:layer`:

1. Writes the layer's `composer.json` with `"type": "layer"` and its PSR-4 namespaces.
2. Adds a path repository for the layer's folder to the root `composer.json`, such as `./functional/*`, once per folder.
3. Requires `"functional/orders": "*"` in the root `composer.json`.

After `composer update functional/orders`, Laravel discovers the layer's provider.

:::warning
`osdd:layer` overwrites the files of a layer that already exists, including its `composer.json`. To add files to an existing layer, use the [generators](/commands/make-commands).
:::

## Examples

### An API layer

```bash
php artisan osdd:layer functional/invoices \
    --target-path="$(pwd)/functional" \
    --generators=migration \
    --generators=model \
    --generators=factory \
    --generators=controller \
    --generators=service-provider \
    --generators=routes
```

### An infrastructure layer

```bash
php artisan osdd:layer technical/feature-flags \
    --target-path="$(pwd)/technical" \
    --generators=service-provider
```
