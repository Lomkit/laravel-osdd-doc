title: Service Provider
description: Wire a layer's migrations, seeders, routes, policies and views into the application.
---

Every layer has a service provider. It extends `Lomkit\Osdd\LayerServiceProvider` instead of Laravel's `ServiceProvider`, which adds three methods: `loadSeeders()`, `overrideConfigFrom()` and `withRouting()`.

```php [functional/orders/src/Providers/OrdersServiceProvider.php]
<?php

namespace Functional\Orders\Providers;

use Functional\Orders\Database\Seeders\OrdersSeeder;
use Lomkit\Osdd\LayerServiceProvider;

class OrdersServiceProvider extends LayerServiceProvider
{
    public function boot(): void
    {
        if ($this->app->runningInConsole()) {
            $this->loadMigrationsFrom(__DIR__ . '/../../database/migrations');
            $this->loadSeeders([OrdersSeeder::class]);
        }

        $this->withRouting(
            web: __DIR__ . '/../../routes/web.php',
            api: __DIR__ . '/../../routes/api.php',
            commands: __DIR__ . '/../../routes/console.php',
            channels: __DIR__ . '/../../routes/channels.php',
        );
    }

    public function register(): void
    {
        $this->overrideConfigFrom(__DIR__ . '/../../config/orders.php', 'orders');
    }
}
```

This is close to what `osdd:layer` generates with the `service-provider` generator.

## Registering the provider

Laravel boots the provider because the layer's `composer.json` lists it:

```json [functional/orders/composer.json]
"extra": {
    "laravel": {
        "providers": [
            "Functional\\Orders\\Providers\\OrdersServiceProvider"
        ]
    }
}
```

`osdd:layer` and `osdd:provider` add this entry for you. Run `composer update functional/orders` once after adding a provider so Laravel rebuilds its package manifest. Do not list layer providers in `bootstrap/providers.php`.

## Migrations

`loadMigrationsFrom()` comes from Laravel. It adds the layer's migrations to `php artisan migrate`:

```php
$this->loadMigrationsFrom(__DIR__ . '/../../database/migrations');
```

## Seeders

`loadSeeders()` registers seeders for [`osdd:seed`](/commands/osdd-seed). Lower priorities run first:

```php
$this->loadSeeders([OrdersSeeder::class, OrderStatusesSeeder::class]);

$this->loadSeeders([RolesSeeder::class], priority: -10);
```

`osdd:seeder` adds this call when it creates a seeder. A seeder you write by hand needs it too.

## Configuration

`overrideConfigFrom()` merges a layer's config file over a key that is already loaded. The layer's values win. Call it from `register()`, see [Configuration](/layers/configuration).

## Routes

`withRouting()` mounts the layer's route files with Laravel's conventions. See [Routing](/layers/routing).

## Policies

Laravel discovers a policy that sits in the `Policies` namespace of its model's layer, the same way it does for `app/`:

| Model | Policy found |
|-------|--------------|
| `Functional\Orders\Models\Order` | `Functional\Orders\Policies\OrderPolicy` |
| `Functional\Users\Models\User` | `Functional\Users\Policies\UserPolicy` |

`osdd:policy OrderPolicy --model=Order --layer=functional/orders` creates the policy in that namespace. Register a policy that lives elsewhere by hand:

```php
use Illuminate\Support\Facades\Gate;

public function boot(): void
{
    Gate::policy(Order::class, OrderAccessPolicy::class);
}
```

## Views and translations

Load the layer's views and translations under a namespace of your choice:

```php
public function boot(): void
{
    $this->loadViewsFrom(__DIR__ . '/../../resources/views', 'orders');
    $this->loadTranslationsFrom(__DIR__ . '/../../lang', 'orders');
}
```

Then use them with the namespace prefix: `view('orders::index')`, `__('orders::messages.placed')`. `osdd:view` writes views to the layer's `resources/views/` folder.

## Commands, observers and events

Anything a Laravel service provider does works in a layer provider:

```php
public function boot(): void
{
    Order::observe(OrderObserver::class);

    Event::listen(OrderPlaced::class, SendOrderConfirmation::class);

    if ($this->app->runningInConsole()) {
        $this->commands([PruneAbandonedOrders::class]);
    }
}
```

:::tip
Keep each layer's wiring in its own provider. A provider that registers classes of another layer hides a dependency that `composer.json` does not show.
:::
