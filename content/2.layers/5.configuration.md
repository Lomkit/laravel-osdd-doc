## The osdd config

The package reads the `osdd` config key:

```php [technical/osdd/config/osdd.php]
return [
    'layers' => [
        'paths' => [
            'functional' => base_path('functional'),
            'technical'  => base_path('technical'),
        ],
    ],

    'boundaries' => [
        'ignore' => [],
    ],

    'events' => [
        'discover' => false,
    ],
];
```

| Key | Default | Description |
|-----|---------|-------------|
| `layers.paths.functional` | `base_path('functional')` | Folder of the business layers |
| `layers.paths.technical` | `base_path('technical')` | Folder of the infrastructure layers |
| `boundaries.ignore` | `[]` | Class prefixes and layer pairs that [`osdd:check`](/commands/osdd-check) does not report, see [Boundaries](/layers/boundaries#ignoring-a-dependency) |
| `events.discover` | `false` | Discover the listeners of every layer, see [Events](/layers/events). Must be a boolean. |

The key of each path is also the vendor of the layers created in it: `osdd:layer functional/orders` creates the layer in the `functional` path. In a terminal, `osdd:layer` without a name asks which path to use.

## Where it lives

`osdd:start` deletes the root `config/` folder and creates the `technical/osdd` layer instead. Its provider overrides the package defaults with the layer's file:

```php [technical/osdd/src/Providers/OsddServiceProvider.php]
<?php

namespace Technical\Osdd\Providers;

use Lomkit\Osdd\LayerServiceProvider;
use Lomkit\Osdd\Seeders\LayersSeeder;

class OsddServiceProvider extends LayerServiceProvider
{
    public function boot(): void
    {
        if ($this->app->runningInConsole()) {
            $this->loadMigrationsFrom(__DIR__ . '/../../database/migrations');
        }
    }

    public function register(): void
    {
        $this->overrideConfigFrom(__DIR__ . '/../../config/osdd.php', 'osdd');

        $this->app->bind('DatabaseSeeder', LayersSeeder::class);
    }
}
```

The provider also loads the cache and jobs migrations of the skeleton, and binds [`LayersSeeder`](/api-reference/seeder-registry#layersseeder) as the default seeder of `db:seed`.

:::note
`Technical\Osdd\Providers\OsddServiceProvider` belongs to your application. The package's own provider is `Lomkit\Osdd\OsddServiceProvider`.
:::

The package does not publish its config file: `vendor:publish` has nothing to copy for `Lomkit\Osdd\OsddServiceProvider`. Change the settings in `technical/osdd/config/osdd.php`. A project that keeps its root `config/` folder can also create `config/osdd.php` by hand.

## Adding a layer folder

Add a path to `technical/osdd/config/osdd.php`:

```php [technical/osdd/config/osdd.php]
return [
    'layers' => [
        'paths' => [
            'functional' => base_path('functional'),
            'technical'  => base_path('technical'),
            'support'    => base_path('support'),
        ],
    ],
];
```

`osdd:layer support/mailing` now creates the layer in `support/` and registers a `./support/*` path repository with the first layer you create there.

## Overriding another package's config

Laravel's `mergeConfigFrom()` keeps the values that are already loaded: a package uses it to fill in its defaults. `overrideConfigFrom()` does the opposite: the layer's values win, like a file in the application's `config/` folder.

```php [technical/horizon/src/Providers/HorizonServiceProvider.php]
public function register(): void
{
    $this->overrideConfigFrom(__DIR__ . '/../../config/horizon.php', 'horizon');
}
```

```php [technical/horizon/config/horizon.php]
return [
    'path' => 'admin/horizon',
    'middleware' => ['web', 'auth'],
];
```

| Method | Who wins | Runs |
|--------|----------|------|
| `mergeConfigFrom()` | The values already loaded | In `register()` |
| `overrideConfigFrom()` | The layer's values | In `register()`, skipped when the config is cached |

:::warning
Call `overrideConfigFrom()` from `register()`, not `boot()`. Packages read their config while they boot: Horizon reads `horizon.path` and `horizon.middleware` to register its routes. An override applied in `boot()` may come too late.
:::

### Maps and lists

Maps are merged key by key, at every depth: nested keys you leave out keep their value. A list replaces the loaded list as a whole, and an empty array clears the loaded value:

```php
// loaded:          ['queues' => ['default', 'low'], 'timeout' => 60]
// layer file:      ['queues' => ['high']]
// result:          ['queues' => ['high'], 'timeout' => 60]
```

Write the full list in the layer file when you want to keep some of the loaded items.

### Generating a config file

```bash
php artisan osdd:config orders --layer=functional/orders
```

The command creates `functional/orders/config/orders.php` and adds this line to the `register()` method of the layer provider:

```php
$this->overrideConfigFrom(__DIR__ . '/../../config/orders.php', 'orders');
```

## Cached configuration

`php artisan config:cache` stores the merged result. `overrideConfigFrom()` does nothing once the config is cached, so run `config:cache` again after changing a layer's config file.
