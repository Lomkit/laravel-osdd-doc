---
title: Basics
description: What a layer is, what it contains and how OSDD finds it.
---

A layer is a Composer package that lives in your repository, under one of the folders listed in `osdd.layers.paths`: `functional/` and `technical/` by default.

## Anatomy of a layer

```
functional/orders/
├── composer.json                 ← "type": "layer"
├── config/
│   └── orders.php
├── src/
│   ├── Models/Order.php
│   ├── Http/Controllers/OrderController.php
│   ├── Policies/OrderPolicy.php
│   └── Providers/OrdersServiceProvider.php
├── database/
│   ├── migrations/
│   ├── factories/OrderFactory.php
│   └── seeders/OrdersSeeder.php
├── routes/
│   ├── web.php
│   ├── api.php
│   ├── console.php
│   └── channels.php
└── tests/
    ├── Feature/
    └── Unit/
```

Only `composer.json` is required. The generators create the other folders when you first need them.

## The layer's composer.json

OSDD treats a folder as a layer when its `composer.json` has `"type": "layer"`:

```json [functional/orders/composer.json]
{
    "name": "functional/orders",
    "type": "layer",
    "require": {
        "lomkit/laravel-osdd": "*"
    },
    "autoload": {
        "psr-4": {
            "Functional\\Orders\\": "src/",
            "Functional\\Orders\\Database\\Seeders\\": "database/seeders/",
            "Functional\\Orders\\Database\\Factories\\": "database/factories/"
        }
    },
    "extra": {
        "laravel": {
            "providers": [
                "Functional\\Orders\\Providers\\OrdersServiceProvider"
            ]
        }
    }
}
```

- `name` is the layer's identifier: the `--layer` option of every generator takes it, and `osdd:phpunit` names the layer's test suite after it.
- The first `psr-4` entry is the layer's root namespace. Generators write classes under it.
- `extra.laravel.providers` lets Laravel discover the layer's service provider, like any package.

A layer that depends on another one requires it:

```json [functional/billing/composer.json]
"require": {
    "lomkit/laravel-osdd": "*",
    "functional/orders": "*"
}
```

## Naming

The package name gives the namespace: each segment is converted to PascalCase.

| Layer | Namespace | Service provider |
|-------|-----------|------------------|
| `functional/orders` | `Functional\Orders` | `OrdersServiceProvider` |
| `functional/external-accounts` | `Functional\ExternalAccounts` | `ExternalAccountsServiceProvider` |
| `technical/feature-flags` | `Technical\FeatureFlags` | `FeatureFlagsServiceProvider` |

Layer names use lowercase letters, numbers and hyphens.

## functional or technical

| Folder | Holds | Examples |
|--------|-------|----------|
| `functional/` | Business domains. A domain owns its models, rules, HTTP layer and tests. | `users`, `orders`, `billing` |
| `technical/` | Infrastructure shared by several domains, with no business meaning. | `osdd`, `auth`, `feature-flags` |

OSDD handles both folders the same way: the split is organizational. Avoid catch-all layers such as `common` or `shared`: they end up holding everything, and every other layer depends on them.

## Discovery

OSDD scans every folder of `osdd.layers.paths`. A sub-folder whose `composer.json` has `"type": "layer"` is a layer. Any other sub-folder is scanned in turn, so you can group layers:

```
functional/
  billing/
    invoices/     ← layer "functional/invoices"
      composer.json
    payments/     ← layer "functional/payments"
      composer.json
  orders/         ← layer "functional/orders"
    composer.json
```

Once a folder is a layer, OSDD does not look inside it for more layers.

## Registration

`osdd:start` and `osdd:layer` register each layer in the root `composer.json`:

```json [composer.json]
{
    "require": {
        "functional/orders": "*",
        "technical/osdd": "*"
    },
    "repositories": [
        { "type": "path", "url": "./functional/*" },
        { "type": "path", "url": "./technical/*" }
    ]
}
```

One path repository per folder covers every layer inside it. After `composer update functional/orders`, Composer symlinks the layer into `vendor/` and Laravel discovers its service provider. `bootstrap/providers.php` stays empty.
