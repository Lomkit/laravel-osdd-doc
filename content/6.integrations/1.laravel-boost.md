Laravel OSDD ships a [Laravel Boost](https://github.com/laravel/boost) skill. With it, a coding agent knows that an OSDD project has no `app/` folder: it creates layers with `osdd:layer`, generates classes with the `osdd:*` commands and `--layer`, and wires seeders, config and routes through the layer's provider.

## Installation

Install Boost in your project, then pick `lomkit/laravel-osdd` when it lists the packages that ship guidelines and skills:

```bash
composer require laravel/boost --dev
php artisan boost:install
```

Boost copies the `laravel-osdd` skill into your agent's skills folder and records the package in `boost.json`:

```json [boost.json]
{
    "packages": [
        "lomkit/laravel-osdd"
    ]
}
```

## Keeping it up to date

The skill follows the package version. Refresh it after each update of `lomkit/laravel-osdd`:

```bash
php artisan boost:update
```

:::note
Coming from `xefi/laravel-osdd`? Replace the package name in `boost.json` before you run `boost:update`, or Boost removes the skill. See the [upgrade guide](/upgrade/from-2x#laravel-boost).
:::

## What the skill covers

- Detecting an OSDD project and finding the layer that owns a concept, starting from `osdd:list --json` and `osdd:graph --format=json`.
- Never writing to `app/`, `database/` or the root `config/`, and never running a bare `make:*` command.
- Creating a layer with `--requires`, and generating code inside it with `--layer`. Without a terminal, `--layer` is required and `osdd:start` or `osdd:remove` need `--force`: the skill only passes it when you asked for the change.
- Wiring migrations, seeders, config overrides, routes, views, components and commands in the layer's `LayerServiceProvider`.
- Declaring a layer before using its classes, and running `osdd:check --format=json` before finishing a change.
- Livewire components and Filament resources in layers, when those packages are installed.
- Running `osdd:seed` and `osdd:phpunit` after a change.
