This documentation covers Laravel OSDD 3.x, the current version, for Laravel 13. An assistant that learned an older version may suggest 2.x code: give it these pages instead. Laravel 12 applications stay on Laravel OSDD 2.x, and the [upgrade guide](/upgrade/from-2x) lists the differences.

## Laravel Boost skill

Laravel OSDD ships a [Laravel Boost](https://github.com/laravel/boost) skill. With it, a coding agent knows that an OSDD project has no `app/` folder: it creates layers with `osdd:layer`, generates classes with the `osdd:*` commands and `--layer`, and wires seeders, config and routes through the layer's provider.

### Installation

Install Boost in your project, then pick `lomkit/laravel-osdd` when it lists the packages that ship guidelines and skills:

```bash
composer require laravel/boost --dev
php artisan boost:install
```

Boost copies the `laravel-osdd` skill into your agent's skills folder and records the package in `boost.json`:

```json [boost.json]
{
    "packages": [
        "lomkit/laravel-osdd"
    ]
}
```

### Keeping it up to date

The skill follows the package version. Refresh it after each update of `lomkit/laravel-osdd`:

```bash
php artisan boost:update
```

:::note
Upgrading from 2.x? Update the package name in `boost.json` before you run `boost:update`, or Boost removes the skill. The [upgrade guide](/upgrade/from-2x#laravel-boost) shows the change.
:::

### What the skill covers

- Detecting an OSDD project and finding the layer that owns a concept, starting from `osdd:list --json` and `osdd:graph --format=json`.
- Never writing to `app/`, `database/` or the root `config/`, and never running a bare `make:*` command.
- Creating a layer with `--requires`, and generating code inside it with `--layer`. Without a terminal, `--layer` is required and `osdd:start` or `osdd:remove` need `--force`: the skill only passes it when you asked for the change.
- Wiring migrations, seeders, config overrides, routes, views, components and commands in the layer's `LayerServiceProvider`.
- Declaring a layer before using its classes, and running `osdd:check --format=json` before finishing a change.
- Running `osdd:seed` and `osdd:phpunit` after a change.

## llms.txt and Markdown copies

The site publishes its pages in formats that assistants read well:

| URL | Content |
|-----|---------|
| [`/llms.txt`](https://laravel-osdd.lomkit.com/llms.txt) | The index of every page, with its description and a link to its Markdown copy |
| [`/llms-full.txt`](https://laravel-osdd.lomkit.com/llms-full.txt) | Every page of the 3.x documentation in one Markdown file |
| `/raw/<path>.md` | The Markdown copy of one page, such as [`/raw/concepts/boundaries.md`](https://laravel-osdd.lomkit.com/raw/concepts/boundaries.md) |

On every page, the **Copy page** button copies the page as Markdown. Its menu also opens the Markdown copy, or opens ChatGPT or Claude with a prompt that points to it.

## MCP server through GitMCP

[GitMCP](https://gitmcp.io) serves a GitHub project as a remote MCP server. Its GitHub Pages address for this site, `https://lomkit.gitmcp.io/laravel-osdd-doc`, reads the site's `llms.txt`, and its tools let the assistant fetch the Markdown copy of any page.

::code-group

```bash [Claude Code]
claude mcp add --transport http laravel-osdd https://lomkit.gitmcp.io/laravel-osdd-doc
```

```json [Cursor (~/.cursor/mcp.json)]
{
    "mcpServers": {
        "laravel-osdd": {
            "url": "https://lomkit.gitmcp.io/laravel-osdd-doc"
        }
    }
}
```

```json [VS Code (.vscode/mcp.json)]
{
    "servers": {
        "laravel-osdd": {
            "type": "http",
            "url": "https://lomkit.gitmcp.io/laravel-osdd-doc"
        }
    }
}
```

::

The server exposes `fetch_laravel_osdd_doc_docs`, which returns the `llms.txt` index, and `fetch_generic_url_content`, which fetches a page from it. For other clients, see the [GitMCP documentation](https://github.com/idosal/git-mcp).

:::note
The site is static: it has no MCP endpoint of its own. Use the GitMCP address above.
:::

## Context7

[Context7](https://context7.com) indexes library documentation for coding assistants. Laravel OSDD is listed as [`/lomkit/laravel-osdd-doc`](https://context7.com/lomkit/laravel-osdd-doc), which indexes the 3.x pages of this site.

With the [Context7 MCP server](https://github.com/upstash/context7) installed, name the library in your prompt to skip the library search:

```
Add a billing layer that requires orders. use library /lomkit/laravel-osdd-doc
```
