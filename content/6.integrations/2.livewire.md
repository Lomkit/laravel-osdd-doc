title: Livewire
description: Register and generate Livewire components inside layers.
---

With [Livewire](https://livewire.laravel.com) 4 installed, a layer can hold its own Livewire components and register them under the layer name: `<livewire:orders::cart />`. Livewire is optional: OSDD does not require it, and the calls below do nothing without it.

```bash
composer require livewire/livewire:^4.0
```

## Registering a layer's components

Call `withLivewire()` in the `boot()` method of the layer provider:

```php [functional/orders/src/Providers/OrdersServiceProvider.php]
public function boot(): void
{
    $this->withViews(__DIR__ . '/../../resources/views');
    $this->withLivewire();
}
```

`withLivewire()` registers, under the layer's package name:

| Component | Lives in | Use it as |
|-----------|----------|-----------|
| Class component | `src/Livewire/Cart.php`, class `Functional\Orders\Livewire\Cart` | `<livewire:orders::cart />` |
| Single-file component | `resources/views/livewire/⚡cart.blade.php` (or `cart.blade.php`) | `<livewire:orders::cart />` |
| Multi-file component | a `resources/views/livewire/cart/` folder | `<livewire:orders::cart />` |

A class component renders a layer view, such as `view('orders::livewire.cart')`, so the provider also needs `withViews()`. In tests, use the same name: `Livewire::test('orders::cart')`.

### Namespace

The default namespace is the layer's package name. Pass another one as argument:

```php
$this->withLivewire('shop'); // <livewire:shop::cart />
```

As with [views and components](/guides/views-and-components#the-namespace), a second provider claiming the same namespace throws `Lomkit\Osdd\Resources\ResourceNamespaceCollisionException` at boot, and a provider outside every layer throws `Lomkit\Osdd\Layers\ProviderLayerNotFoundException`.

`withLivewire()` derives every path from the layer and takes no path argument. A layer with another folder layout registers it with `Livewire::addNamespace()` itself.

## Generating components

`osdd:livewire` is the twin of `make:livewire`. It is only registered when Livewire 4 is installed.

```bash
php artisan osdd:livewire search --layer=functional/orders
# functional/orders/resources/views/livewire/⚡search.blade.php, <livewire:orders::search />

php artisan osdd:livewire Cart --class --layer=functional/orders
# functional/orders/src/Livewire/Cart.php
# functional/orders/resources/views/livewire/cart.blade.php

php artisan osdd:livewire Admin/OrderList --class --layer=functional/orders
# <livewire:orders::admin.order-list />
```

| Option | Description |
|--------|-------------|
| `--layer` | The layer, as for every [generator](/commands/make-commands#the-layer-option) |
| `--class`, `--sfc`, `--mfc`, `--type=` | The component type. Defaults to `livewire.make_command.type`, `sfc` with Livewire's config. |
| `--test` | Also write a test. A class component's test goes to the layer's `tests/Feature/Livewire/`; single-file and multi-file tests sit next to the component, as in Livewire. |
| `--emoji=`, `--js`, `--css` | As with `make:livewire` |

The command adds `$this->withLivewire();` to the layer provider, and `withViews()` for a class component, when the provider does not call them yet. It prints `Registered [livewire:orders] in [...]`, or the line to add by hand when the layer has no provider.

- Pass the name without a namespace: `billing::invoice` is generated in the `--layer` layer as `invoice`.
- When another layer has the same package name, it warns and writes `withLivewire('functional-orders')`.
- An existing component fails with `Component already exists.` and exit code 1.

:::warning
Do not use `make:livewire` in an OSDD project: it writes into `app/Livewire` and the root `resources/views`.
:::
