---
title: osdd:list
description: List the layers with their providers, requirements, file counts and health.
---

`osdd:list` shows every discovered layer: where it lives, what it contains, what it requires, and whether it is wired correctly.

```bash
php artisan osdd:list
```

```
  functional/orders ............................................ functional/orders
  Namespace ............................................................ Functional\Orders\
  Providers ......................... Functional\Orders\Providers\OrdersServiceProvider
  Requires .............................................................. functional/users
  Models ........................................................................... 3
  Migrations ....................................................................... 4
  Seeders .......................................................................... 1
  Tests ........................................................................... 12
  Route files ...................................................................... 2
  Health ............................................... no test suite in phpunit.xml

  INFO  1 layer listed.
```

The command never changes anything and always exits with 0. Layers are sorted by name.

## Options

| Option | Description |
|--------|-------------|
| `--json` | Print the layers as JSON, for scripts and coding agents. |

## JSON output

```bash
php artisan osdd:list --json
```

```json
{
    "layers": [
        {
            "name": "functional/orders",
            "path": "functional/orders",
            "namespace": "Functional\\Orders\\",
            "providers": ["Functional\\Orders\\Providers\\OrdersServiceProvider"],
            "requires": ["functional/users"],
            "counts": {"models": 3, "migrations": 4, "seeders": 1, "tests": 12, "route_files": 2},
            "health": {
                "required": true,
                "path_repository": true,
                "installed": true,
                "provider_extends_layer_service_provider": true,
                "test_suite": false
            }
        }
    ],
    "invalid_manifests": [
        {"file": "functional/billing/composer.json", "error": "it has no \"name\"."}
    ]
}
```

| Key | Content |
|-----|---------|
| `path` | Layer folder, relative to the project |
| `namespace` | Root namespace of the layer |
| `providers` | The `extra.laravel.providers` of the layer |
| `requires` | The discovered layers in its `require`; other packages are left out |
| `counts.models` | `.php` files under the `Models` folder of the source directory |
| `counts.migrations` | `database/migrations/*.php` files, sub-folders not included |
| `counts.seeders` | `.php` files under `database/seeders` |
| `counts.tests` | `*Test.php` files under `tests/` |
| `counts.route_files` | `routes/*.php` files |
| `invalid_manifests` | Layer `composer.json` files OSDD could not read, relative to the project, with the reason |

With no layer, the output is `{"layers": [], "invalid_manifests": []}`.

## Health

The text output shows the problems in the `Health` row: `not required in composer.json`, `no path repository`, `not installed`, `no test suite in phpunit.xml`, or `OK`. In the JSON output, each of these flags tells what to fix when it is `false`:

| Flag | Fix |
|------|-----|
| `required` | Add `"vendor/package": "*"` to the `require` of the root `composer.json` |
| `path_repository` | Add a `path` repository covering the layer to the root `composer.json` |
| `installed` | Run `composer update vendor/package` |
| `test_suite` | Run [`osdd:phpunit`](/commands/osdd-phpunit) |

## Providers

Any provider is healthy, and so is a layer without one. A layer may declare a provider that does not extend `Lomkit\Osdd\LayerServiceProvider`, such as a Horizon or Telescope provider. Once the layer is installed, the `Providers` row marks such a class:

```
  Providers ... Technical\Horizon\Providers\HorizonServiceProvider (not a LayerServiceProvider)
```

The [generators](/commands/make-commands#generators-that-wire-the-provider) never edit such a provider: they use another provider of the layer that extends `LayerServiceProvider`, or print the line to add.

In the JSON output, `provider_extends_layer_service_provider` is information, not a problem:

| Value | Meaning |
|-------|---------|
| `true` | Every provider of `extra.laravel.providers` extends `LayerServiceProvider` |
| `false` | At least one provider does not |
| `null` | The layer has no provider, or is not installed, so its provider classes cannot be loaded yet |

## Invalid composer.json files

A layer `composer.json` that cannot be read is listed with its error, marked `INVALID`, and the command keeps listing the valid layers:

```
  functional/billing/composer.json ............................................. INVALID
  Error ................................................................. it has no "name".

  INFO  1 layer listed.

  WARN  1 invalid layer manifest skipped.
```

See [Invalid composer.json files](/concepts/layers#invalid-composerjson-files) for what makes a file invalid.

:::tip
A folder you expect is missing? Its `composer.json` lacks `"type": "layer"`, is invalid, the folder is not under a path of `osdd.layers.paths`, or a stale [layer cache](/commands/osdd-cache) hides it: run `php artisan osdd:clear`.
:::
