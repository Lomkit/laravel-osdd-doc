## Project commands

| Command | Description |
|---------|-------------|
| [`osdd:start`](/commands/osdd-start) | Convert a fresh Laravel project to layers |
| [`osdd:layer`](/commands/osdd-layer) | Create a layer and register it in the root `composer.json` |
| [`osdd:list`](/commands/osdd-list) | List the layers with their providers, requirements, file counts and health |
| [`osdd:check`](/commands/osdd-check) | Check that each layer only uses the layers it requires, and that no requirements form a cycle |
| [`osdd:graph`](/commands/osdd-graph) | Print the layer graph in Mermaid, DOT or JSON |
| [`osdd:seed`](/commands/osdd-seed) | Run the seeders registered by every layer, or by some layers |
| [`osdd:phpunit`](/commands/osdd-phpunit) | Sync `phpunit.xml` with the test suite and source directory of each layer |
| [`osdd:remove`](/commands/osdd-remove) | Remove a layer that no other layer requires |
| [`osdd:cache`, `osdd:clear`](/commands/osdd-cache) | Cache the discovered layers, or remove that cache |

`php artisan about --only=osdd` shows the discovered layers, the migration paths and the number of registered seeders:

```
  OSDD .............................................................
  Layers ........................................................ 2
  Migration paths .... functional/users/database/migrations, technical/osdd/database/migrations
  Seeders ....................................................... 1
  functional/users ..................................... functional/users
  technical/osdd ......................................... technical/osdd
```

Laravel sorts the rows. `php artisan about --only=osdd --json` puts them under the `o_s_d_d` key: `layers`, one key per layer, `migration_paths` and `seeders`.
