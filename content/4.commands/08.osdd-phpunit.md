---
title: osdd:phpunit
description: Sync phpunit.xml with the test suite and source directory of each layer.
---

`osdd:phpunit` adds a `<testsuite>` to `phpunit.xml` for each layer that has a `tests/` folder, and adds each layer's source directory to the code coverage.

```bash
php artisan osdd:phpunit
```

## Options

| Option | Description |
|--------|-------------|
| `--prune` | Remove the test suites of layers that no longer exist, and the literal `<source><include>` directories that resolve to no folder, such as `app` after `osdd:start`. Entries with a glob are kept. |

## What it does

1. Reads `phpunit.xml` at the root of the project. It fails if the file or its `<testsuites>` element is missing, or if a layer `composer.json` is invalid.
2. Adds a test suite named after each layer that has a `tests/` folder and no suite yet.
3. Adds each layer's source directory, such as `functional/orders/src`, to `<source><include>`, unless an entry [already covers it](#entries-that-already-cover-a-layer).
4. With `--prune`, removes the suites and include directories that are gone.
5. Writes the file back when something changed.

That is one test suite and one source include per layer, and nothing else. It writes no `<source><exclude>` entry: a layer's `src` holds no migrations. The exclusions already in the file stay.

Each change prints one line:

```
  Testsuite functional/orders → functional/orders/tests ............. ADDED
  Coverage source functional/orders/src ............................. ADDED
  Testsuite functional/users → functional/users/tests ............... ADDED
  Coverage source functional/users/src .............................. ADDED

  INFO  phpunit.xml updated.
```

Run it again after creating a layer: entries already present are left alone and not listed. When nothing changes, it prints only `phpunit.xml is already up to date.`. With `-v`, it also names the layers that get no test suite because they have no `tests/` folder.

:::note
Without `--prune`, the command only adds entries. [`osdd:remove`](/commands/osdd-remove) removes the entries of the layer it removes; after deleting a layer by hand, run `osdd:phpunit --prune`.
:::

## Result

After [`osdd:start`](/commands/osdd-start), with the `functional/users` and `functional/orders` layers, `php artisan osdd:phpunit --prune` changes Laravel's `phpunit.xml` like this:

```diff [phpunit.xml]
         <testsuite name="Feature">
             <directory>tests/Feature</directory>
         </testsuite>
+        <testsuite name="functional/orders">
+            <directory>functional/orders/tests</directory>
+        </testsuite>
+        <testsuite name="functional/users">
+            <directory>functional/users/tests</directory>
+        </testsuite>
     </testsuites>
     <source>
         <include>
-            <directory>app</directory>
+            <directory>functional/orders/src</directory>
+            <directory>functional/users/src</directory>
         </include>
     </source>
```

```
  Testsuite functional/orders → functional/orders/tests ............. ADDED
  Coverage source functional/orders/src ............................. ADDED
  Testsuite functional/users → functional/users/tests ............... ADDED
  Coverage source functional/users/src .............................. ADDED
  Coverage source app: the directory no longer exists ............... REMOVED

  INFO  phpunit.xml updated.
```

Layers are added in name order, after the entries already there. The rest of the file is left as it is: an added entry takes the indentation of its neighbours (spaces or tabs), a removed one leaves no blank line, and the head of the file, the attributes of `<phpunit>` and the line endings do not change. `git diff` shows only the lines added or removed. [`osdd:remove`](/commands/osdd-remove) writes the file the same way.

## Entries that already cover a layer

`osdd:phpunit` reads `<source><include>` as PHPUnit does: each `<directory>` is trimmed, taken relative to the folder of `phpunit.xml`, and expanded with `glob()`, where `**` stands for zero or more folders. A layer's source directory is not added when one of these entries already covers it:

| Entry | Covers `functional/orders/src` |
|-------|--------------------------------|
| `<directory>functional/*/src</directory>` | Yes |
| `<directory>functional/**/src</directory>` | Yes |
| `<directory>./functional/orders/src/</directory>` | Yes, the same path written another way |
| `<directory>functional</directory>` | Yes, a parent folder |
| `<directory prefix="Order">functional/*/src</directory>` | No, the prefix filters the files |
| `<directory suffix=".inc">functional/*/src</directory>` | No, another suffix |

A glob or a parent folder counts only without `prefix`, and with the `.php` suffix or none.

To cover every layer of a folder with one entry, prefer `functional/*/src` to `functional`, which also reads the migrations, seeders and tests of the layers. Test suites stay one named entry per layer.

## Pruning

`--prune` removes:

- the test suites named after a layer that no longer exists;
- the `<source><include>` directories without a glob character (`*`, `?`, `[`) that resolve to no folder.

An entry with a glob, such as `functional/*/src`, is never removed: it may match folders created later.

```
  Testsuite functional/legacy: the layer no longer exists ........... REMOVED
  Coverage source functional/legacy/src: the directory no longer exists  REMOVED
```

## Running a layer's tests

```bash
# One layer
php artisan test --testsuite=functional/orders

# Every suite
php artisan test
```

See [Tests and CI](/guides/testing-and-ci) to write tests in a layer and run them in CI.

:::tip
The `osdd:phpunit` command needs the `dom` PHP extension, a requirement of the package.
:::
