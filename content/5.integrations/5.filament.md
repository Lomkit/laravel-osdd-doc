---
title: Filament
description: Discover the Filament resources, pages, widgets and clusters of every layer.
---

With [Filament](https://filamentphp.com) 5 installed, each layer can hold the Filament classes of its domain. The `LayersPlugin` panel plugin discovers them. Filament is optional: OSDD does not require it.

```bash
composer require filament/filament:^5.0
```

## Registering the plugin

Add the plugin to every panel that should see the layers, in the application's panel provider, after `->id()`:

```php [AdminPanelProvider.php]
use Filament\Panel;
use Lomkit\Osdd\Filament\LayersPlugin;

public function panel(Panel $panel): Panel
{
    return $panel
        ->id('admin')
        ->path('admin')
        ->plugin(LayersPlugin::make());
}
```

## Where the classes live

Each layer keeps the classes of a panel in `src/Filament/{Panel}/`, where `{Panel}` is the panel id in StudlyCase: `admin` gives `Admin`, `back-office` gives `BackOffice`.

```
functional/orders/src/Filament/
└── Admin/
    ├── Resources/
    │   └── Orders/OrderResource.php   ← Functional\Orders\Filament\Admin\Resources\Orders\OrderResource
    ├── Pages/
    ├── Widgets/
    └── Clusters/
```

For each discovered layer with an `autoload.psr-4` namespace, the plugin calls Filament's `discoverResources()`, `discoverPages()`, `discoverWidgets()` and `discoverClusters()` on these folders. A panel only sees the folder named after its id: `OrderResource` above shows in the `admin` panel only.

The plugin also registers each layer's `src/Filament` as a Filament component location, with the layer's package name as view namespace.

## Generating classes in a layer

There is no `osdd:filament-*` generator: use Filament's own commands. Once the plugin is registered on the panel, they offer the folders of every layer. In a script, pass the layer namespaces:

```bash
php artisan osdd:model Order --migration --factory --layer=functional/orders

php artisan make:filament-resource Order --panel=admin \
    --resource-namespace='Functional\Orders\Filament\Admin\Resources' \
    --model-namespace='Functional\Orders\Models'
```

The resource lands in `functional/orders/src/Filament/Admin/Resources/Orders/`.

- `--resource-namespace` must be one of the namespaces the panel lists (`$panel->getResourceNamespaces()`); Filament falls back to the first folder otherwise.
- `make:filament-page` and `make:filament-widget` have no namespace option. When the panel discovers a single page (or widget) folder they write there; otherwise they ask for the namespace in a search prompt that lists every discovered folder. Run them in a terminal, or move the generated class and view afterwards.
- A page view goes to the layer's `resources/views/filament/...` (`orders::filament.admin.pages.reports`) when the layer provider calls `withViews()`.

:::warning
Do not pass `--model`, `--migration` or `--factory` to `make:filament-resource`. Filament then calls `make:model`, `make:migration` and `make:factory`, which write into `app/` and `database/`. Generate them first with `osdd:model ... --layer=...`.
:::

## In production

`php artisan optimize` runs `filament:optimize`, which caches the discovered classes with `filament:cache-components`, as for `app/Filament`. Run it again after adding a class.

:::tip
A layer resource that does not show in the panel? Check that the panel calls `->plugin(LayersPlugin::make())`, that the folder is named after the panel id, and that `filament:cache-components` did not cache the panel before the class was added.
:::
